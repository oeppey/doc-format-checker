# T-02：ELECTRA 初筛阈值标定报告

日期：2026-09-30 ｜ 环境：zzx 服务器，CUDA（6×RTX 4090 之 GPU 5 共享卡）｜ 模型：ChineseErrorDetectorElectra（revision b58d6b）｜ 脚本：[threshold\_sweep.py](../scripts/threshold_sweep.py)（可复现）

## 方法

* 正确句：19 份人工 fixtures 去重后仅 16 句（同源模板，多样性不足），另以「主语 × 动作 × 事项」槽位合成 240 句公文句式补足，共 **256 句**。

* 错句：对正确句注入混淆词表错字（布署/按排/贯彻等），全部 139 条为词级注入，带注入位置标注。

* 一次推理（threshold=0）收集全部字符分数，离线扫 0.50–0.95 共 10 个阈值。

* **局限**：注入错句分布不等于真实错字分布，合成句文体单一；本报告用于定阈值**区间**，不是精度验收。上线前仍需真实卷宗标注集复核。

## 扫描结果（CPU 与 CUDA 数值完全一致，模型跨设备确定）

| 阈值       | 错句召回      | 字级命中      | 正确句误报     | 进入精检比例    |
| -------- | --------- | --------- | --------- | --------- |
| 0.50     | 1.000     | 0.871     | 0.754     | 0.841     |
| 0.60     | 1.000     | 0.806     | 0.590     | 0.734     |
| 0.70     | 0.993     | 0.784     | 0.461     | 0.648     |
| **0.80** | **0.978** | **0.741** | **0.344** | **0.567** |

| 0.90     | 0.928     | 0.626     | 0.188     | 0.448     |

## 吞吐（GPU 5，与 SFT 服务共享中实测）

| 批量 | 吞吐            | 备注                       |
| -- | ------------- | ------------------------ |
| 8  | 280 句/秒       | 约为本机 CPU（28.6 句/秒）的 10 倍 |
| 32 | **916.9 句/秒** | 约为 CPU 的 32 倍；模型加载 4.5 秒 |

一页公文约 20–40 句：初筛耗时在 GPU 上可忽略（<0.1 秒），瓶颈在 4B 精检的逐句 0.85 秒。

## 结论与推荐

1. **推荐默认阈值 0.85**：错句召回 96.4%，正确句误报 26.6%，约一半句子进入精检。
   召回优先场景（公文错别字容忍度低）可用 0.80（召回 97.8%，精检比例升至 56.7%）；
   0.90 以上召回跌破 93%，不建议作为默认值。当前代码默认 0.5 过于宽松（误报 75%），**建议改为 0.85**。
2. 字级命中率（0.85 时 69%）明显低于句级召回——ELECTRA 的嫌疑字符只能当提示，
   不能当定位依据；项目现状（提示注明「仅供参考」，定位由 4B 差分产生）与此结论一致，保持不变。
3. 门控价值成立：0.85 阈值下 4B 调用量减半；若无门控，每句 0.85 秒的精检对长文档不可接受。
4. 后续：真实卷宗标注集到位后复扫（替换合成池）；`--batch-size` 建议服务端默认 32。

复现：`export CED_MODEL_DIR=<权重目录>` 后执行 `.venv/bin/python scripts/threshold_sweep.py --device cuda --batch-sizes 8,32`，完整数据在 `data/threshold_sweep.json`（不入库）。
